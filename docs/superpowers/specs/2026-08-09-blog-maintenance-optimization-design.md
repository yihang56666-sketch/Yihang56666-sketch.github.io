# 博客维护整理与体验优化设计

## 目标

在不改变现有 Vanilla HTML/CSS/JS SPA、hash 路由和 GitHub Pages 发布方式的前提下，把博客整理成更容易长期维护、浏览和阅读的版本。

本轮成功标准：

- 首页、归档、文章、项目、阅读、关于和 404 页面在桌面与移动端都能完成主要浏览路径。
- 首页只保留一套实际使用的渲染路径，删除明显未使用的旧首页渲染器，避免内容和行为分叉。
- CSS 保留现有白色动漫视觉方向，但消除旧主题的大块重复覆盖，建立清晰的基础层、页面层和首页主题层边界。
- 搜索、主题切换、移动端导航、返回顶部、文章目录、代码复制和旧路径兼容继续可用。
- 每个 hash 路由动态更新 `title`、description、Open Graph、canonical 和 JSON-LD；无效路由为 `noindex` 并显示可恢复入口。
- 交互控件具有可见焦点、可访问名称和足够的触控尺寸；`prefers-reduced-motion` 下不强制播放装饰动效。
- 不虚构新的个人经历、项目事实或文章内容；内容更新仅限于修正明显过时的界面文案、统计展示和维护说明。

## 方案与边界

采用温和重构：保留现有数据数组、组件函数风格、图片素材、CDN 图标和 augmented-ui 依赖，不引入框架、构建工具或新的服务端能力。

明确不做：全文搜索索引、CMS/Markdown 迁移、评论系统、RSS 生成、第三方分析、重新绘制全部视觉资产，以及无用户事实依据的个人内容扩写。

## 结构整理

### JavaScript

- 以 `renderHomeMaikire` 为唯一首页渲染入口，保留它依赖的卡片和栏目辅助函数。
- 删除未被路由调用的 `renderHome`、`renderHomeV2` 和仅服务于旧首页的 `editorialBoard` 等代码；删除后用语法检查和路由浏览确认无引用遗漏。
- 将与路由无关的展示计算保留为纯函数，避免渲染时修改数据数组。
- 把主题按钮的状态同步集中处理：切换后同时更新根节点 class、按钮 `aria-label` 和图标语义；读取本地存储失败时回退到默认主题，不阻断首屏。
- 搜索输入只绑定一次并在重新渲染后恢复焦点与查询值，避免输入事件重复注册。
- 统一外部链接的 `target`/`rel`，对数据生成的 URL 继续使用转义函数；不放宽 HTML 注入边界。

### CSS

- 保留当前生效的浅色/深色 token 和首页 Maikire 视觉层，删除前置旧 cyberpunk token 与仅被旧首页使用的样式块。
- 将全局基础、站点壳层、内页组件、首页组件、响应式和动效规则按模块排列；同一选择器只保留一个主要定义，必要的主题覆盖集中在对应模块附近。
- 统一响应式断点，优先确保 390px、480px、768px、1080px 和桌面宽度下不出现横向滚动、文字溢出或按钮挤压。
- 为固定格式控件保留稳定尺寸：导航图标按钮、搜索框、卡片封面、文章目录和返回顶部按钮不得因 hover 或动态内容改变布局。
- 保留动效但降低非必要装饰层的默认密度；所有新增或保留的动画都补入 reduced-motion 规则。

### HTML 与元信息

- 修正首页和 404 的基础标题、描述、语言、favicon 和资源路径一致性。
- 为首页补齐可分享的 Open Graph 基础字段；动态路由继续由 JS 更新，不把 hash 页面误写成多个静态 canonical 文件。
- 404 页面继续只承担 GitHub Pages fallback，不在其中复制业务逻辑。

## 用户体验

- 首页第一屏明确站点身份、内容类型和两个主要入口；滚动后先看到最近文章，再看到分类、阅读和站点更新。
- 文章卡片显示标题、分类、日期、阅读时长和摘要，搜索无结果时给出返回归档的恢复动作。
- 文章页维持左侧信息轨道与正文目录，移动端把元信息和目录变成连续可读区块。
- 主题切换不改变当前路由和滚动位置；页面刷新后恢复用户选择。
- 移动导航打开时可操作、可关闭，导航链接点击后自动收起；键盘用户可通过跳过链接和可见焦点进入正文。

## 数据流与错误处理

路由变化 -> `parseRoute()` -> 对应 `render*()` -> `afterRender()` -> 元信息、图标、动效和交互增强。渲染函数只消费已有数据，找不到文章、项目、标签或分类时进入统一的 `renderNotFound()` 或空状态。

本地存储、剪贴板、图标 CDN 和 IntersectionObserver 都视为可选增强：能力不可用时保留核心页面和文字操作，不让异常冒泡阻断渲染。动态元信息使用现有的 upsert 辅助函数，避免重复插入 head 节点。

## 验证

- `node --check assets/app.js`。
- 启动本地静态服务器，用 Playwright 访问首页、归档、文章、项目详情、阅读、关于、标签、分类和不存在路由。
- 在 1440x1000、768x1024、390x844 三个视口检查截图、横向溢出、导航、搜索和文章目录。
- 验证亮/暗主题切换、刷新后主题持久化、`prefers-reduced-motion`、剪贴板不可用时的回退提示和旧路径 fallback。
- 检查每个路由的 `document.title`、description、canonical、robots 和 JSON-LD；检查控制台无未处理错误。
- 只对本轮修改文件做 diff 审阅，保留用户已有未提交改动。
